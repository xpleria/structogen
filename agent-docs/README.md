## Lifecycle rules

- **Lore is living memory.** Organize by enduring subject, not workstream, date, or session. Integrate new lessons with existing knowledge, remove duplication, replace obsolete statements in place, and delete dead statements. Lore holds no status, plans, or open items.
- **Forge is active work.** Create one topic folder per workstream only after owner sign-off authorizes commencement. Each topic index states goal, scope, sign-off, status, reading guide, and map. A playbook is added when there is a method to preserve; a plan when work is staged; a progress file once work happens. The progress file is the single source of status. Paused work stays in forge with its reason.
- **Horizon is future work.** Keep one topic folder per future workstream. Its index records what the work is and why it matters, where it came from, known constraints and prerequisites, and what is needed to start. Horizon status does not authorize work.
- **Transitions follow owner sign-off on the work, not on document moves.** Commencement moves a topic to forge; acceptance weaves verified facts into the facts tree and lessons into lore, moves any deferred remainder to horizon, sheds process material, and deletes the forge topic; deferral moves remaining work to horizon; cancellation keeps lessons in lore and sheds the rest. Partial acceptance moves only the accepted part.
- Record each required sign-off in the receiving topic index as a date plus a reference. Agent judgment, passing tests, and successful deployment are not acceptance. If uncertain whether a statement was sign-off, ask.
- Do not create a forge topic merely to store an unverified claim; use the related authorized forge topic if one exists, otherwise record it in horizon. Keep proposed decisions out of settled facts until accepted.
